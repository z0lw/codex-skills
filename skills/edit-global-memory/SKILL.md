# グローバルメモリの編集

## 1. 変える必要があるかを先に決める

- 現在の `~/.codex/AGENTS.md` を全文読み、本人の依頼と後続の訂正を原文で確かめる。
- 既存の規則を今回の出来事に当てはめれば判断が決まるなら、本文は変えない。規則を当てはめなかった失敗として、元の作業を直す。
- 既存の規則だけでは決まらない新しい好みや方針が、本人の言葉から確定した時だけ本文を変える。関係する規則を書き直して組み込み、同じ趣旨の注意文を重ねない。
- 叱責や同じ失敗の繰り返しだけを、新しい規則を足す理由にしない。今回だけの事情を全作業の規則へ広げない。

## 2. 編集は別の担当に任せ、親が照合する

編集の検討や試行で会話を散らかさないよう、編集は会話の履歴を引き継がないサブエージェント1体に任せる。任せても、結果の責任は親が持つ。

- 担当のモデルと推論の強さは、`~/.codex/agents/` の役割設定に置き、このスキルの本文には書かない。モデルが新しくなった時は、役割設定だけを書き換える。役割設定がなければ、親と同じモデルを使う。

  ```toml
  # ~/.codex/agents/memory_editor.toml
  name = "memory_editor"
  description = "Edits ~/.codex/AGENTS.md for the edit-global-memory skill."
  model = "<使うモデル>"
  model_reasoning_effort = "high"
  ```

- 親は担当に、AGENTS.md の場所、本人の依頼と訂正の原文（発言の順のまま）、問題になった応答や操作を渡す。親の修正案は渡さない。
- 担当は、変更が要るかを判断する。要る時は差分案と根拠（本人の原文、既存の規則のどこに何が足りないか）を親へ返し、この時点ではファイルを変えない。
- 親は差分案を本人の原文と既存の規則に照らし、意味が保たれているか、要らない追記がないかを確かめてから、同じ担当に反映を頼む。根拠が足りない案は、理由を添えて同じ担当へ戻す。

## 3. 書き方

- 一文に一つの判断を書く。条件を動作の前に置き、例外は条件の近くに書く。
- 「だけ」「明示」「同じ範囲」など範囲を決める語、固有名、数値、本人が指定した表現は原文どおり保つ。
- 「必ず」を増やすことを修正の代わりにしない。理由は、適用範囲の理解に役立つ時だけ短く書く。
- 統合や削除は、元の各場面で同じ判断になる時だけ行う。

## 4. 容量

- 本文は UTF-8 で 30,000 バイト以内にする。もっと小さく保ちたい時は `--limit` で上限を下げる。本人が特に必須と指定した要件を最終節 `## 本人指定の必須要件` に置いた場合、その節は数えない。
- 編集の前後に検査する。

  ```bash
  python3 ~/.codex/skills/edit-global-memory/scripts/check_memory_size.py ~/.codex/AGENTS.md
  python3 ~/.codex/skills/edit-global-memory/scripts/check_memory_size.py ~/.codex/AGENTS.md --limit 5000
  ```

- 上限に収めるために、必要な条件や例外を落とさない。収まらない時は重複を統合し、それでも収まらなければ反映せず、試したことを本人へ報告する。

## 5. 確かめて報告する

- `git -C ~/.codex diff --check` と実際の差分を読み、意味の保持と変更の必要性を確かめる。`~/.codex` を Git で管理していれば、確かめた変更だけをコミットする。
- 本人への最終応答に、何を条件にどの動作を変えたか（追加・取消・書き換え・統合・削除）を書く。「メモリを更新しました」だけで済ませない。変更しなかった時は、その理由を一文で添える。
