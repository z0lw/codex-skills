# yomiyasu

誰が何をどうするかを読み取れる、自然な日本語へ整える。原文の事実、条件、主張の強さ、書き手の文体を保つ。

## 他の日本語表現スキルとの分担

日本語表現の共通方針はこのスキルで扱う。同じ文への校正指示を重ねず、用途固有の判断を必要なスキルへ分ける。スキルを削除したり、設定で無効化したりする必要はない。

- 一般の文章、技術記事、業務文書、エッセイはyomiyasuで整える。
- スライドは[japanese-slide-writing](../japanese-slide-writing/SKILL.md)も読み、見出しと本文・図表の対応、用語、比較軸、研究上の留保を確認する。レイアウトや生成・表示検証は利用中のプレゼンテーションスキルに従う。
- 論文などの日本語原稿は、AGENTS.mdに指定された監修経路も守る。このスキルによる推敲を監修の代わりにしない。
- 通常の会話や作業報告は、AGENTS.mdの敬語・呼称・禁止表現・短さを優先する。校正用の見出しや改善点一覧を毎回付けない。

## 推敲の進め方

更新版の[上流手順](references/upstream-skill.md)を読み、以下のローカル適用方針と合わせて使う。上流手順にある`references/`と`scripts/`の相対参照は、このスキルのルートから解決する。用途分担・依頼された出力形式・AGENTS.mdを優先し、他のスキルを無効化する指示として使わない。

用途と対象範囲を指示・原稿から判断する。指定された文体・書式を優先し、必要な用途の資料だけを読む。

- 技術記事・設計説明は[tech](references/domains/tech.md)。原稿にある手順や仕組みを分かりやすくつなぐ。
- 仕様書・PR説明・報告書は[business](references/domains/business.md)。責任主体と条件・結果を明確にする。
- 個人ブログ・noteは[essay](references/domains/essay.md)。書き手の実感と感情を保ち、壮大な教訓を加えない。

係り受けや主述関係の修正には[gemini-syntax.md](references/gemini-syntax.md)、不自然な語彙・構文の見直しには[slop-catalog.md](references/slop-catalog.md)を参照する。これら上流資料の固定的な数値・禁止・出力形式は、以下の適用方針で調整する。

推敲前に原文の主張、比重、言い切りの強さ、文の働きを確認する。文書全体の用件と段落の目的を保ち、予定・実動作・完了報告を混同しない。語句を置き換える前に、主述・修飾・指示先、条件・例外・否定・並列の掛かる範囲を点検する。

1. 動作主・対象・条件が紛れる文だけを具体化する。自明な主語を毎文繰り返さず、原文から特定できない主体や原因を作らない。
2. 比喩や抽象語が意味を曖昧にする場合は、確認できる操作・状態・結果へ直す。専門用語、引用、書き手が意図した表現を一律に置換しない。
3. 不要な前置き、反復、否定対比、装飾を減らす。実際の禁止事項、例外、誤解の訂正に必要な否定は残す。
4. 文長30〜45字、読点0〜2個、箇条書き15%などは見直しの目安とする。数値へ合わせるために条件を削ったり、不自然に分割したりしない。手順・列挙・スライドの箇条書き、必要な注記・単位・略語説明は用途に合わせて残す。
5. 数値、固有名詞、時制、断定の強さ、責任主体、技術的制約を原文と照合する。説明を具体化するために未確認のコード、設定値、体験、効果を付け足さない。

出力は指定された成果物・書式に合わせる。本文の推敲だけを求められたら修正本文を提示し、改善点は求められた場合か判断に必要な変更がある場合だけ短く添える。

## 検査と提出前の照合

最新版の上流手順に従い、原文がある場合は原文のlint、推敲、`yomiyasu_check.py run`によるlint・全文差分・資料との照合、候補の読解、提出直前の`verify`まで進める。新規作成では原文の代わりに根拠資料を渡す。検査の候補数を品質の点数や意味保持の証明にしない。

```bash
python3 ~/.codex/skills/yomiyasu/scripts/yomiyasu_check.py run --source /absolute/path/original.md --final /absolute/path/final.md --material /absolute/path/material.md --fact-gaps --state-dir /absolute/path/.codex/yomiyasu-checks
python3 ~/.codex/skills/yomiyasu/scripts/yomiyasu_check.py verify --final /absolute/path/final.md --state-dir /absolute/path/.codex/yomiyasu-checks
```

新規作成は`--source`を省略して`--material`を渡す。原稿の種類・読み手・立場は実際の用途から判断し、該当する上流の`references/doc-types/`、`audience.md`、`persona.md`等を必要な範囲で読む。本人の経験・志望・成果を推測で補わない。

検査記録は全文を含むため、案件の隠し作業領域へ置く。ユーザー向けObsidianフォルダーへ内部記録を追加しない。ファイル保存しない指定では上流の標準入力と`--no-record`を使い、記録なしではverifyできないことを区別する。通常の短い会話・作業報告は従来どおりAGENTS.mdを優先し、検査のためだけにファイルを作らない。

候補を原文・資料と照合して必要な修正をまとめて1回行い、修正後はrunを再実行する。verify後に本文を変更したらrunとverifyをやり直す。医療・化学・画像処理等の適切な専門用語は保持する。最後に全文を読み、意味・条件・主体・時制と自然さを確認する。
