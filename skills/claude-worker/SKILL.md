# Claude Worker

Claude Code CLI（`claude`）を非対話モードで起動し、タスクを委任して結果をJSONで回収するスキル。前提は `claude` がPATHにあることのみ。

通常のClaudeモデルへの相談・委任はCodex内のサブエージェントを優先する。このスキルはClaude Code CLIが指定された場合、または必要なモデル・実行環境を利用可能かつ許可されたCodex内経路で満たせない場合に使う。該当する単発のレビュー・分析・実作業は、このスキルで起動から結果確認まで進める。委任するという理由だけで `codex-work-orchestration` を併用しない。複数担当の依存関係や編集範囲の調整、スレッド・ホスト間の引渡し、依頼された継続実行が必要な場合に限り、同スキルを併用する。通常の委任にagmsg・Git・daemonは不要。

## 短い相談か、独立作業の委任か

- **通常のClaudeへの短い相談（このスキルの対象外）**: Codex内で利用できる指定モデルのサブエージェントへ、対象文と一つの問いを渡す。CLI経由が指定された短い相談なら同じ最小入力を直接CLIへ渡す。短い相談へ`claude-worker.sh`、8項目の委任契約、長文context、補助機構を追加せず、不要な追問・再実行をしない。
- **独立したレビュー・読取り分析の委任**: 本スキルのCLI適用条件を満たす原稿・コード・資料のレビューや調査・比較・分析に使う。資料が一つでも対象になる。読み取りと回答のみで、編集はさせない（プロンプトに「ファイルを変更しない」を明記）。
- **実作業の委任**: Claudeは割り当てられたスコープ内でファイルを調査・編集し、コマンドやテストを実行し、証跡（変更ファイル・実行コマンドと出力）付きで結果を返す。
- **CLI経由のFable直接相談**: Fableに加えてClaude Code CLI経由が指定された場合、または必要なモデル・実行環境をCodex内で満たせない場合だけ
  [references/direct-fable-consult.md](references/direct-fable-consult.md)
  を全文読み、固定モデル・同一session・安全なstdin経路で相談する。

## 依頼内容と操作範囲

相談・レビューの送信前と検収時は、[相談文と結果の検収](../codex-work-orchestration/references/consultation-models.md#相談文と結果の検収)を適用する。親の案・未確認の前提を利用者の要求として渡さず、必要な独立検討を終えたことまで確かめる。

目的、対象、操作範囲、完了の根拠が分かる短いプロンプトを渡す。以下は確認する情報であり、8つの見出しや定型文を毎回作る必要はない。重なる項目はまとめ、レビューなら対象資料・確認事項・編集禁止・根拠付きの返答を一段落に書いてよい。ラッパーは `bypassPermissions` を使うため、読取り・書込み範囲と禁止する副作用は明示する。既存の許可を超える操作を委任せず、外部送信・公開・認証変更などはその操作に必要な許可を確認する。

1. **objective** — 達成すべきこと
2. **working directory** — 絶対パス（既存ディレクトリ。Gitリポジトリである必要はない）
3. **read/write scope** — 読んでよい範囲と、書き換えてよい範囲
4. **permissions** — 許可する操作（コマンド実行・テスト・ネットワーク等）
5. **forbidden actions** — 禁止事項（スコープ外の編集、未許可の削除・Git変更、ユーザーの手元変更の破棄 等）。Gitの読取りと変更は区別する。
6. **completion criteria** — 完了条件
7. **validation** — 完了の検証方法（実行すべきテスト・確認コマンド）
8. **return format** — 返答形式（変更ファイル一覧、実行コマンドと出力、未解決事項）

## ローカル資料を使う委任

ローカル資料が成果に必要な時だけ正本ルートを渡し、Claude自身に関連資料を探索・読解させる。短い相談や固定された単一資料へ不要な探索を追加せず、親の長い要約を直接読取りの代用にしない。

- 事実の帰属が重要な作業だけ、実際に読んだ資料と判断に効いた出典を返させ、親が主張と出典の対応を確認する。
- 曖昧な資料から人物の属性、発言者、誰が何を言ったかを推定しない。明示的な根拠がなければ不明として残す。

## 起動方法

プロンプトは必ずstdinで渡す（引数渡しはシェル展開事故の元）。ヒアドキュメントは `<<'PROMPT'`（クォート付き）を使う。

新規セッション:

```bash
~/.codex/skills/claude-worker/scripts/claude-worker.sh -C /path/to/workdir <<'PROMPT'
<タスク契約全文>
PROMPT
```

出力はJSON 1件（無加工）。`session_id` を控え、`result` を本文、`is_error` と終了状態を実行結果として確認する。指定モデルは `modelUsage` の実モデル名で照合し、必要な時だけ同じセッションの記録を補う。`-m` の引数やClaude自身の自己申告だけでは、実モデルの一致を確認したことにしない。

継続（回答内容に依存するフォローアップ・修正指示）:

```bash
~/.codex/skills/claude-worker/scripts/claude-worker.sh -C /path/to/workdir -r <session_id> <<'PROMPT'
<追加指示・修正指示>
PROMPT
```

同一タスクの続き・手直し・質問は `-r` で同一セッションに送る。別タスクは新規セッションで始める。ユーザーがモデルを指定した場合は `-m <model>` に正確なモデル名を渡し、続きでもその指定を保つ。モデル・版の指定がない場合は既存の許可と設定に従う。Fable直接相談では `-m fable` で代用せず、参照手順の `-F` を使う。

## 運用ルール

- **直列実行**: 書き込みスコープが重なる委任を並行起動しない。同一作業ディレクトリへの書き込みは1セッションずつ順番に。読み取り専用の相談は並行してよい。
- **ユーザー変更の保全**: 委任中・委任間にユーザーが編集した可能性のあるファイルは、上書き前に現状を読み直してから差分を当てるようプロンプトで指示する。「ユーザーの手元変更を破棄しない」を禁止事項に含める。
- **検収はCodexの責務**: 読取りレビューでは、指摘と根拠を実資料・差分・確認記録に照合する。実作業では変更と必要な動作を確認する。同じ対象・最終版の有効な検証結果は利用し、すべてのコマンドを一律に再実行しない。矛盾や証拠不足がある箇所だけ追加確認する。
- **失敗時**: `is_error` がtrue、または完了条件未達なら、同一セッション（`-r`）へ具体的な修正指示を送る。2回続けて失敗したら契約の切り方から見直す。

## 対話TUIで起動したClaudeの監視

`spawn` 等で対話TUI（別ターミナル・別ペイン）としてClaudeを起動した場合、このスキルの非対話JSON回収は使えない。以下を実行条件とする。

### 生存確認に使ってよい証拠

**必須の第一経路は、対象ターミナルの実画面本文である。**

```bash
osascript -e 'tell application "Terminal" to get contents of selected tab of window 1'
```

tmux内なら `tmux capture-pane -p -t <target>` を使う。画面本文を取得できない時は、取得できないことを未確認として報告し、稼働中と呼ばない。

### 禁止

- `ps` のプロセス存在、CPU時間、経過時間だけで「稼働中」「作業中」「処理中」と判断・報告しない。プロセスが生きていることは、入力待ちで停止している状態と区別できない。
- agmsgの `No new messages.` を「作業が進んでいる」根拠にしない。それは未着信を示すだけで、着手・停止・入力待ちのいずれとも整合する。
- 対象ファイルのmtimeが変わらないことを「まだ書いていないだけ」と解釈しない。停止の兆候として扱う。

### 実画面で必ず判定する状態

取得した画面本文から、次のどれに該当するかを毎回判定する。

| 画面の状態 | 判定 | 次の操作 |
|---|---|---|
| `Enter to confirm`、`❯ 1.`/`2.` の選択肢、`(y/n)`、`Press Enter` 等 | **入力待ちで停止**。作業は1文字も進んでいない | 選択肢の全文を読み、意図に合う項目を選ぶ。読まずにEnterやEscを送らない |
| `Perusing…`、`Thinking…`、`↓ N tokens`、経過秒数が増える | 実稼働中 | そのまま待つ |
| プロンプト `❯` だけで直前に出力がある | 応答完了または待機 | 直近出力を読み、完了か未着手かを判定 |
| エラー、rate limit、認証要求 | 停止 | 同じ経路で復旧。別モデル・別経路へ勝手に代替しない |

### 選択ダイアログの扱い

選択肢が出ている時は、**キーを送る前に選択肢の全文と現在のハイライト位置（`❯`）を読む**。読まずに矢印キーやEnterを送ると、意図しない項目（モデル変更、プラン変更、課金選択など）を確定させる。Escで閉じた結果が既定選択の適用になる場合があるため、Esc後も必ず画面を再取得してヘッダー行のモデル名を確認する。

指定モデル（Fable等）から別モデルへ切り替わっていたら、それは指定経路の逸脱である。稼働していることを理由に継続せず、`/model` で指定モデルへ戻すか、ユーザーへ判断を仰ぐ。

### 監視の間隔と報告

- 起動直後は最初の画面取得を必ず行う。「起動できた」を着手の根拠にしない。spawn直後の1回目こそ入力待ちが出やすい。
- 待機中は、画面本文の取得を主、agmsg受信箱の確認を従とする。受信箱だけを繰り返し見て時間を消費しない。
- ユーザーへ進捗を伝える時は、画面から読み取った実際の表示（実行中のツール名、経過秒、直近の出力行）を根拠にする。根拠なく「作業中です」と書かない。
