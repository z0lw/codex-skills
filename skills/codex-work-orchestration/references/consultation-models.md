# 相談先とFableのモデル選定

## 相談文と結果の検収

- 送信前に、利用者の要求・確認済みの事実と、親が置いた仮説・実装案を分ける。利用者が指定していない方式や入力条件を相談の前提にせず、要求に対する成立条件、別の方法、反例を相談先自身に検討させる。既存案を渡す場合も、その案を採用することへの同意を求めない。
- 利用場面の判断を相談する時は、定型表現・正常系・自作の期待値だけを入力の代表にしない。原依頼と実資料を渡し、親の想定から外れる入力でも必要な結果が得られるかを確認させる。ユーザーが定めた範囲・方式・評価軸は保ち、独立検討を口実に変更しない。
- 修正後の相談を「致命的な問題だけ」「以前の指摘が直ったかだけ」に狭め、原要件の再検討を省かない。親は回答の根拠、置かれた前提、実出力を照合し、相談先の同意やテスト通過を要件充足の代用にしない。前提の誤りが見つかったら、相談文と依存する実装・評価を直して同じ担当へ戻す。

## モデルと経路

- 相談・独立監査は明示依頼、または不確実性・影響が高く判断が変わる時に限ります。無修飾の短い相談は通常のClaudeへ必要事項を絞って一問とし、一般のClaude・Fable相談や委任もCodex内のサブエージェントを優先します。Proは `$chatgpt-pro-consult`、Claude Code CLIでの実行・CLI経由の直接Fableが明示された場合は `$claude-worker`、明示された長時間Ultracodeは `$claude-ultracode-consult`、agmsgが明示された場合は `$agmsg` を使います。Fableは利用経路が提供する最新の安定版を使います。Fableの推論強度はMediumを明示して起動・再開します。ユーザーが版を固定していない場合は、起動・再開前に公式モデル情報と利用経路の対応状況を照合し、最新の安定版を選びます。Claude Codeの `fable` aliasがその版に解決される場合はaliasを使い、旧版へ解決されるgatewayや固定上書きがある場合は、確認した最新安定版のIDを明示します。選択可能一覧や引数だけで一致とせず、実行記録のモデルIDも照合します。最新安定版が利用できない場合は同じ経路の対応状況を確認し、黙って旧版へ下げません。ユーザーによる版の固定は優先し、相手・経路・セッション・目的・資料は保ち、採否は親が判断します。
